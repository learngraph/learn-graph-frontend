# Content graph foundation

Status: working architecture. No visual layout or production copy is implied.

## Governing rule

Symmetry may emerge from the architecture; it must never dictate it.

The website is a content graph that may have several visual projections. It is not a graph-shaped interface that content must fill.

## Structural layers

### Territory

A primary orientation domain. A territory must represent a distinct visitor question and contain enough coherent material to justify root-level status.

Territories may have unequal density.

### Cluster — optional

A meaningful grouping inside a territory. Clusters exist only where topics form recognisable families; they are not inserted to regularise layout.

A cluster may be navigational without requiring a standalone article.

### Topic

A stable, addressable conceptual unit with one clear communicative purpose. A topic is not required to look like an article.

### Artifact

Reusable substantiation or application material such as:

- case
- evidence
- application or use context
- video or demonstration
- diagram
- repository, paper, or technical reference

Artifacts can support several topics without being copied into each one. They may have stable addresses without becoming navigation roots.

### Utility

Contact, legal information, language selection, consent, and launch-app actions live outside the editorial graph.

## Content composition

A topic may combine only the blocks its purpose requires:

- editorial prose
- concise key points
- diagram
- media
- evidence or case reference
- technical facts
- links or resources
- action

The current `NodeArticle` shape is a prototype display contract, not the future content architecture.

## Relationships

Relationships are stored because they carry meaning, not because the visualization needs lines. Candidate relation types include:

- contains
- depends on
- explains
- demonstrates
- applies in
- supported by
- implemented through
- contributes to

The visual projection decides which relationships to expose at a given moment. Relationship microcopy is not required to appear inside every node.

## Truth status

Every consequential claim or artifact should be distinguishable as:

- current capability
- observed or verified evidence
- proposed application
- principle or commitment
- direction or roadmap
- requires verification

Proposals and commitments must never be presented as achieved impact.

## Addressing

- Public routes describe the concept, not the current visualization.
- Territories and topics receive stable canonical paths.
- Optional cluster segments are used only if they improve conceptual clarity.
- Artifacts can have independent stable identities and appear contextually inside several topics.
- Palette and presentation state remain independent from content identity.

## Territory review card

Each territory is reviewed through the same questions:

1. Why does this territory deserve root status?
2. Which visitor question does it answer?
3. Which topics are genuinely distinct and necessary?
4. Do natural clusters exist?
5. What content already exists, and where?
6. What must be written, demonstrated, or verified?
7. Which artifacts support which claims?
8. Which cross-links change understanding?
9. What is duplicated or homeless?
10. Which decisions require owner judgment?
